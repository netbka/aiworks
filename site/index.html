Plan once, check every result, decide only what needs you

AIWorks is a manager for AI coding agents that runs on your own Windows computer. You approve a plan; an AI builder does each step in an isolated copy; a fresh AI session checks that exact version; and nothing in your folder changes until you press Apply.

Synthetic demonstration. Every screen below was captured from a disposable runtime with two fictional projects, notes (a plain folder) and site (a local Git repository), and a synthetic AI worker that makes no model or network call. The computer name in the header is replaced with “Example PC”.

It is not an installation, nobody's real projects appear in it, and this page makes no claim about any installed or running copy of AIWorks.

Three different answers, kept apart

This page talks about one of them at a time and says which.

  • In the source code

    What the repository's code can do. Some of it is off until its setting is switched on in the AIWorks configuration file.

  • Shown in this demonstration

    What the scripted owner journey did, step by step, on the production entry points of that source, with its settings on. Each step's outcome was recorded and checked by the script.

  • On your computer

    Which version is installed, and what it runs. Only that computer can tell. Merged source is not deployed, and a passing demonstration is not a running service.

The owner journey

The owner journey acceptance runs 29 checked steps. These are the ones you can see. Shown in this demonstration applies to every step in this section.

1. Start from nothing

Home answers “What changed, and what needs me?”. With no projects it says so and offers Add project: an idea first, then a folder on this computer.

  • Confirming a project's rules is a protected owner action. It passed the Windows check that the request came from the owner's browser, not from an AI worker.
  • Off by default Add project needs projectConnection.enabled; planning and starting work from the page need coordinator.intake.

2. Agree on a plan, version by version

Ask for a plan and the planner drafts one: goal, done when, included, later, estimate and main steps. Edit plan saves a new version and lists what changed from the last one.

  • An unsent edit survived leaving the page and coming back.
  • Approve and start admits exactly the version on screen, and nothing starts before it.
  • Plan groups plans as Now, Next and Later, with their version history.

The Plan tab

Each approved plan with its priority, version and estimate. Approval stays on Review, for the version it shows.

3. Review the checked result, then Apply it yourself

The builder worked in an isolated copy. A separate checker approved that exact version, and Review shows it, named by its commit.

  • Try this version opens the checked pages in a sealed frame that cannot reach the dashboard or the internet. Desktop and phone screenshots of it were taken under the same containment as the workers.
  • Apply refused while the owner had changed the same file and wrote nothing; it then applied and kept an unrelated owner edit.
  • Undo apply refused while the owner had edited an applied file, then put the folder back byte for byte.
  • For the local Git project, Apply refused a dirty working tree, then fast-forwarded the branch; a builder that tried to press Apply from inside its job was refused.

4. A step stops for your decision

When a step needs the owner, it stops, nothing in the folder changes, and it appears in Needs you and on Home under its project.

  • The answer was written on the project's Overview; its draft was kept across navigation.
  • The next builder run received the answer, and its result was checked again.
  • Checked by hand in the acceptance run: answering with the keyboard alone, Tab to Send answer, with a visible focus ring.

5. Releases say what is true

A project without GitHub is never released: its results are applied from Review. Publish is not available, and the page says why.

  • Owner-reserved A manual Publish button is not built. Release destinations need the owner's explicit grant; this demonstration had none.

6. Alerts, rehearsed

The decision raised an alert. The rehearsal transport recorded it on this computer as it would be sent: nothing was sent and nothing was reported delivered.

  • Alert rules, a Knowledge fact and the project budget were each saved through the same owner check.
  • Owner-reserved Real delivery needs a recipient the owner configures. None was configured.

On a phone

Below 960px the navigation moves to the bottom. At a 320px window and a 390px phone, none of the 13 checked screens scrolled sideways.
