# Development status

This document describes source capabilities only. Installation status, connected projects, campaign progress, machine names and private operational evidence belong outside the public repository.

Four kinds of evidence are kept apart below, and none is promoted into another:

- **Source:** the code is merged into this repository. Merged is not deployed.
- **Synthetic check:** a test in this repository, or the scripted [owner journey](design/OWNER_JOURNEY_ACCEPTANCE.md), exercised it with fictional projects, synthetic AI workers and disposable folders. No model, network, GitHub, account or real destination was involved.
- **Unavailable:** it needs something this repository cannot supply: an owner decision, an owner grant, an account, or a person. The prerequisite is named.
- **Installation:** whether any installation runs a given revision, with which switches, is unknown here. An installation's own status command and dashboard say so; an upgrade follows [SUPERVISOR.md section 6](SUPERVISOR.md#6-installation-and-maintenance). No installation, upgrade or runtime revision is evidenced in this repository.

A design document in `docs/design/` is not proof that its feature is built, enabled or deployed. [PROJECT_WORKSPACE_PLAN.md](PROJECT_WORKSPACE_PLAN.md) and the designs are kept as written for their history; this page says what the source does now.

## The core loop (on by default)

The code includes a persistent SQLite-backed supervisor, bounded worker sessions in Windows job containment, independent verification of the exact head, ordered provider fallback, restart recovery, a coordinator inbox and a loopback dashboard (`src/supervisor/controller.mjs`, `store.mjs`, `campaign.mjs`; `src/dashboard/`). Executable runtime code must be merged before new work starts ([AW-005](DECISIONS.md#aw-005---runtime-code-must-be-merged-declarations-remain-private)). Campaign declarations are private local data. Synthetic checks: `tests/supervisor/supervisor.test.mjs`, `restart.test.mjs`, `restart-publish.test.mjs`, `restart-parallel.test.mjs`, `merged-code.test.mjs`, `process.test.mjs`.

Coordinator plans and replies stay in the local dashboard. Requests retain their selected repository and run separately. Registered campaign publication uses its declared target repository.

Nothing here is a blanket "done": the four groups below are kept apart.

**Finished in source, with synthetic acceptance.** Production Windows owner actions; project connection, intake, Plan, decisions, Review, Apply and Undo apply for local projects; project budgets; the alert outbox with the rehearsal and Telegram transports; static and server previews of a checked version with desktop and phone screenshots; the disposable release rehearsal; the scheduler's and routed dispatch's activation packages (RUN10, MOD7: critical tests and runbooks); local trust; the executor feasibility review; the static showcase source. **Needs the installation's operator, after independent acceptance of the exact head.** Switching the scheduler on (RUN10) and routed dispatch on for a cohort (MOD7: settle each account's models, record the baseline, run and compare the cohort); declaring a project's server preview script after accepting its outgoing-network limit; self-hosting, cleanup, program waves and CAAM (SELF13, CLN2, PROG5, the pilot); upgrading an installation to a reviewed revision. None of these is evidenced here, and a merged revision is not a deployed one.

**Needs a person.** The blind usability session ([USABILITY_SESSION](design/USABILITY_SESSION.md)): script and success measures prepared, not run.

**Owner-deferred.** Notifications that leave the computer (owner decision of 2026-10-21), remote dashboard access and phone push (WP10, AW-003), real release destinations, the canary and a Publish action (AW-010 grant), and hosting the showcase. They stay off until the owner reopens them.
